Let the agent write the code.Keep production safe.

aycod is one small binary that stands between your AI coding agent and your repository. It runs your own checks, refuses the shortcuts, and gives the same verdict in CI on every pull request.

curl -fsSL https://github.com/AyenaCode/aycod/releases/latest/download/install.sh | sh

Linux and macOS, Intel and Arm. The script checks the download's SHA-256 and installs to ~/.local/bin.

On Windows, aycod is not available natively yet. It runs on Linux and macOS today.

The shortcuts agents take, and what aycod answers

An agent under pressure to finish will reach for the fastest way to green. aycod reads every command and every edit before it runs, and answers in the agent's own format.

  • Force-pushing, or pushing straight to main

    Refused in every form, including --force-with-lease and +refspec. Rejected by aycod: force push is forbidden.

  • Skipping the git hooks with --no-verify

    Refused, along with git -c, hook path tricks and GIT_CONFIG_*. Rejected by aycod: bypassing git hooks (--no-verify) is forbidden.

  • Reading .env, keys and cloud credentials

    Refused by name, through the shell and the read tool. Rejected by aycod: reading secrets is forbidden (.env).

  • Silencing the linter or skipping a test

    eslint-disable, @ts-ignore, it.skip, .only, #[ignore] fail the check unless the owner justifies them with AYCOD-OK: <reason>.

  • Declaring victory while the tests fail

    The agent cannot end its turn, commit or push until your checks pass. It gets the failing task, the command and the end of the log, enough to fix it on the first try.

  • Editing the rules that judge it

    aycod.toml, the git hooks and the agent's own settings are protected. Your lint and test configs need your approval to change.

Two places, one verdict

The same binary and the same aycod.toml on the developer's machine and in CI. What passes locally passes in the pipeline, and what slips past a laptop is caught before it merges.

On your machine

  • Hooks for Claude Code, Codex CLI and Copilot CLI check every command and edit.
  • Git hooks run the checks on every commit and refuse unsafe pushes, for any agent and any human.
  • Unchanged project, nothing to run: the cached check answers in about 6 ms.
# what aycod install sets up, and what is really active
aycod doctor

In CI, on every pull request

  • aycod ci runs the fast checks, then the slower ones (coverage, audit, end-to-end), with full logs on failure.
  • Works in GitHub Actions, GitLab CI or any runner: it is one binary, no service.
# .github/workflows/ci.yml
- run: curl -fsSL https://github.com/AyenaCode/aycod/releases/latest/download/install.sh | sh
- run: echo "$HOME/.local/bin" >> "$GITHUB_PATH"
- run: aycod ci

Start in a minute

Four commands in an existing project. Nothing changes in how you start your agent.

  1. Install aycod

    Once per machine. It must be on your PATH: the hooks call it by name.

    curl -fsSL https://github.com/AyenaCode/aycod/releases/latest/download/install.sh | sh

  2. Describe your checks

    Writes a commented aycod.toml for sveltekit, rust, go or generic. Review the tasks it lists.

    aycod init --stack sveltekit

  3. Put the guardrails in place

    Git hooks, the hooks of the agents it finds, and the rules in AGENTS.md.

    aycod install

  4. Check what is protected

    Every layer, the missing tools, and anything an agent has disabled.

    aycod doctor

Early, and honest about it

aycod is at v0.1. The guard, the end-of-turn gate, the git hooks and aycod ci are tested end to end. The agent hooks are tested against each agent's documented formats, and recorded sessions with each agent come next. A shell cannot be parsed perfectly, so aycod refuses what it cannot resolve, and CI remains the line that runs off the agent's machine.
